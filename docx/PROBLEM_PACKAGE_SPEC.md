# Problem Package ZIP Spec

Last reviewed: 2026-05-22

This is the portable problem format for importing problems generated by other tools or agents. The goal is simple: one ZIP should contain metadata, one Markdown statement, and paired test data files.

## Recommended Directory Shape

```text
problem-package.zip
├── config.yml
├── statement.md
├── README.md              optional, ignored by importer
└── cases/
    ├── 1.in
    ├── 1.out
    ├── 2.in
    └── 2.out
```

Files may be nested in folders, but test case filenames must be unique by simple filename. Do not include both `cases/1.in` and `extra/1.in`.

## Required Files

Metadata file, one of:

- `config.yml`
- `config.yaml`
- `config.md`
- `problem.yml`
- `problem.yaml`
- `problem.config.yml`
- `problem.config.yaml`
- `problem.config.md`
- `metadata.yml`
- `metadata.yaml`
- `metadata.md`
- `*.config.yml`
- `*.config.yaml`
- `*.config.md`

Statement file, one of:

- `statement.md`
- `problem.md`
- `*.statement.md`

Test case files:

- input: `.in`
- expected output: `.out` or `.ans`

Examples:

```text
1.in + 1.out
2.in + 2.ans
sample-1.in + sample-1.out
```

The importer rejects packages with no valid paired cases.

## Metadata Format

The parser intentionally supports a simple key-value YAML-like format. Do not use nested YAML objects. Arrays such as `[基础, 输入输出]` are treated as comma-separated text.

Recommended `config.yml`:

```yaml
slug: a-plus-b
title: A + B Problem
difficulty: Easy
tags: [基础, 输入输出]
timeLimitMs: 1000
memoryLimitKb: 262144
visible: true
samples: [1]
scores: 1=20, 2=80
```

Equivalent simple Markdown-style config is also accepted:

```markdown
# Problem Metadata

- slug: a-plus-b
- title: A + B Problem
- difficulty: Easy
- tags: 基础, 输入输出
- time_limit_ms: 1000
- memory-limit-kb: 262144
- visible: true
- samples: 1
- scores: 1=20,2=80
```

Supported keys:

| Key | Required | Notes |
| --- | --- | --- |
| `title` | yes | Problem title. |
| `slug` | no | Unique URL slug. If omitted, backend generates one from ZIP name/title plus time. |
| `difficulty` | no | Defaults to `Easy`. |
| `tags` | no | Stored as comma-separated tag names on the problem row. |
| `timeLimitMs` / `timeLimit` | no | Milliseconds. Defaults to `1000`, minimum `100`. |
| `memoryLimitKb` / `memoryLimit` | no | Kilobytes. Defaults to `262144`, minimum `16384`. |
| `visible` | no | Defaults to `true`. Accepts `true/false`, `yes/no`, `1/0`, `on/off`, `visible/hidden`, `可见/隐藏`. |
| `samples` / `sampleCases` | no | Case basenames to expose as samples, comma or semicolon separated. |
| `scores` | no | Score map like `1=20,2=80`. Missing cases share the remaining points. Explicit total cannot exceed 100. |

Key names are case-insensitive and ignore spaces, underscores, and hyphens. For example, `time_limit_ms`, `time-limit-ms`, and `timeLimitMs` are equivalent.

## Statement Markdown

The statement file is stored as the full problem statement. Put all description, input/output requirements, constraints, notes, and examples here. The admin UI no longer splits input and output description into separate fields.

Recommended `statement.md`:

```markdown
# A + B Problem

Read two integers and output their sum.

## Input

Two integers `a` and `b`.

## Output

One integer, `a + b`.

## Constraints

$1 \le a, b \le 10^9$
```

The frontend renders Markdown and KaTeX math. Prefer LaTeX syntax for formulas:

- inline math: `$1 \le n \le 100000$`
- block math:

```text
$$
-10^9 \le a_i \le 10^9
$$
```

Avoid writing complex expressions with `_`, `^`, `<`, or `<=` directly in normal Markdown text because Markdown/HTML parsing may treat them as formatting or tags.

## Example ZIP Content

The admin problem list provides a downloadable example ZIP. The current example contains:

```text
localoj-problem-package-example.zip
├── config.yml
├── statement.md
├── README.md
└── cases/
    ├── 1.in
    ├── 1.out
    ├── 2.in
    └── 2.out
```

`config.yml` in the example:

```yaml
slug: a-plus-b
title: A + B Problem
difficulty: Easy
tags: [基础, 输入输出]
timeLimitMs: 1000
memoryLimitKb: 262144
visible: true
samples: [1]
```

`statement.md` in the example:

```markdown
# A + B Problem

Read two integers and output their sum.

## Input

Two integers `a` and `b`.

## Output

One integer, `a + b`.

## Constraints

$1 \le a, b \le 10^9$
```

Test data:

```text
cases/1.in   -> 1 2
cases/1.out  -> 3
cases/2.in   -> 40 2
cases/2.out  -> 42
```

`README.md` is included only for humans. The importer ignores it.

## Import Limits And Safety

- ZIP file names are read as UTF-8.
- Total uncompressed package size is limited to 128 MB.
- A single file inside the package is limited to 64 MB.
- Paths containing `..` or Windows drive prefixes are rejected.
- Unrelated files are ignored unless they are accepted config, statement, or test data files.
- Test data is stored under `/data/problems/{problemId}/cases/` after import.
- Submitted programs never receive raw problem data directories directly; the worker reads test data and sends stdin to go-judge per case.
